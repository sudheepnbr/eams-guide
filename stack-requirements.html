System requirements

Server

  • Windows Server or Windows 10/11 (PROD uses a Windows service), or Linux with ODBC + SQL Server reachable.
  • CPU/RAM sized for concurrent hospital users and SCORM/package uploads (E-Learning video materials can be large).
  • Disk for uploads/ (assets, service desk, DMS quarantine/vault, e-learning packages) plus SQL data files.
  • Network: LAN access to SQL Server; optional outbound SMTP and Microsoft App Proxy for external approvers.

Database

  • Microsoft SQL Server 2019+ recommended.
  • ODBC Driver 17 or 18 for SQL Server on the app host.
  • Database created before first run; apply scripts under db/sql/ in order (see install).

Clients

  • Modern Chromium-based browser (Chrome/Edge).
  • HTTPS when using hostname/LAN IP for camera barcode scanning.

Install and first run

  1. Create a virtual environment and install: 
    pip install -r requirements.txt
pip install -r requirements-db.txt
  2. Configure .env with a working DATABASE_URL.
  3. Apply SQL foundation scripts from db/sql/ (start with 001_init_schema.sql, then numbered follow-ons for admin, SSO mapping, modules).
  4. Start the app: 
    python run.py
# or
python -m uvicorn app.main:app --host 0.0.0.0 --port 8010
  5. Open http://127.0.0.1:8010/ — health at /health, OpenAPI at /docs.
  6. PROD Windows: use the provided service scripts / Restart EAMS.bat (Waitress on 8010).

HTTPS for barcode cameras

Set SSL_SAN_IPS (and optional DNS), run scripts/generate_dev_ssl.ps1, trust static/tls/eams-lan.crt on client PCs (or GPO), restart the app.

AD SSO header contract

Reverse proxy / IIS / App Proxy should pass:

  • x-forwarded-user — domain user id
  • x-forwarded-name — display name
  • x-forwarded-email — email
  • x-forwarded-groups — groups separated by ; (configurable)

/api/v1/auth/me upserts core.[User], maps groups via core.ADGroupRoleMap, and writes login audit events.

Canonical portal roles

SUPER_ADMIN, ADMIN, INSTANCE_MANAGER, INSTANCE_TECHNICIAN, MANAGEMENT, AUDITOR, GUEST.

Module menus use service catalog codes such as MODULE_ACCESS_ASSET, MODULE_ACCESS_SERVICE_DESK, MODULE_ACCESS_ELEARNING, MODULE_ACCESS_DMS. Fine-grained actions use the Role Access Matrix and module-specific permission codes.
