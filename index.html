What EAMS is

EAMS is a FastAPI web application with Jinja module screens wrapped by a shared portal layout (session cookie eams_user). JSON APIs live under /api/v1. Module routers live under app/modules/<name>. Schema is applied from db/sql scripts and idempotent ensure_*_schema helpers on first use.

Document Management defaults off until activated in Admin → module activation. Other modules default on.

Shared platform services

  • RBAC — portal roles (SUPER_ADMIN, ADMIN, INSTANCE_MANAGER, …) plus module service codes and Role Access Matrix features.
  • Instance scope — IT / biomedical / facilities style instances via core.UserInstance.
  • AD SSO-ready — trusted headers from reverse proxy / App Proxy; LDAP helpers for directories and assignees.
  • Audit — audit.EventLog for significant actions.
  • Notifications — templates in core.NotificationTemplate; outbound mail via configured SMTP/delivery.
  • Admin Settings — organization masters, users/roles, module activation, mandatory fields, certificate signatories.

Typical production layout

  • Windows host with Microsoft SQL Server and ODBC Driver 17+.
  • App served by Waitress (Windows service EAMSConnect) or Uvicorn on port 8010.
  • Optional HTTPS / reverse proxy (Caddy, IIS, Microsoft App Proxy) for LAN and external approvers.
  • Uploads under uploads/ (not public static); keep backups of DB + uploads.
